# Kitmux v0.6 — reliable native sync and terminal fixes

V0.6 is a reliability release built from a full code review and terminal QA of
v0.5.0. It makes catalog changes reach every client that can accept them, stops
credentials from spreading to unassigned clients, and fixes interactive toggles
that appeared to change without persisting. Catalog schema 3 and existing CLI JSON
formats remain compatible with v0.5.

## Native sync

Each client is synchronized independently. A conflict or write failure in one
client no longer cancels native changes for the others; the command exits nonzero
and names every failed client. Errors name the client, file, entry, and recovery
command.

Conflicts are reported only when an owned entry really differs from what Kitmux
wants:

- Dropped client defaults, such as Codex `enabled = true` or OpenCode
  `disabled: false`, are equivalent to absent fields.
- An owned entry, link, or subagent file deleted outside Kitmux is not a conflict
  when Kitmux also wants it gone.
- `import --refresh --from CLIENT` adopts an external edit or deletion for that
  client only, without pinning group or inherited availability elsewhere.

`sync --check` is clean immediately after an import, so the next unrelated toggle
no longer applies surprise changes. `subagent import` adopts only that client's
subagents and never opts it into MCP or skill management.

## MCP projection and credentials

An MCP is written into a client's configuration only when it is ON for that client
or the client already has the entry. Environment values and other credentials of a
Claude-only server are no longer copied into Codex or OpenCode as disabled entries.
Entries Kitmux created are removed when turned off; imported Codex and OpenCode
entries keep their native disabled form, and Claude entries are removed.

Codex entries omit the default `enabled = true`. Comments that introduce the next
TOML table survive edits and removals, and lowercase `\u` escapes are accepted.
New JSON entries follow the file's indentation without escaped slashes. Managed
bridges keep their existing Kitmux executable while it exists. Claude SSE
endpoints are not projected into clients that support only Streamable HTTP.

## Terminal interface

- The assign dialog changes only the clients you edit. Unchanged clients keep
  following their groups, and a globally OFF item keeps its assignments.
- Bulk toggles continue when the catalog saved but native sync failed, and they
  include marked rows hidden by a collapsed group or search.
- The list reloads when another Kitmux process changes the catalog; this also
  fixes a crash after an external group removal.
- A "Native sync pending" banner and the Clients tab report adoption, ON counts,
  and each client's native check result. Press `f` on Clients to refresh.
- Esc responds immediately, cancelled searches keep the previous filter, empty
  search results say so, long IDs widen with the terminal, doctor output opens in a
  viewer, and an up-to-date skill update reports that nothing changed.

## Skills and subagents

Kitmux owns only the OpenCode permission rules it adds; v0.5 whole-array records
migrate on the first sync, and restore accepts both forms. A Kitmux enable
overrides a native OpenCode deny until restore. Name-based hides are written only
for skills whose projection that client can see. Deleted links are recreated, or
left absent when the skill is off. Installed packages are read-only, Git ignores
inherited repository variables, and extraction depth is bounded.

Subagent renders escape every control character and are parsed back before they
are recorded, so ANSI or C1 text can no longer corrupt the ownership journal;
journals corrupted by v0.5.0 recover on the next sync. Layout checks apply only to
clients with Kitmux-managed subagents. Edits are validated before saving, imported
OpenCode Markdown is disabled in place, IDs differing only by letter case are
rejected, and assignments to clients without a native variant warn, including
through groups.

Imports skip unusable skill and subagent entries with a warning naming the path
instead of aborting. A real skill directory in a discovery location is skipped
with migration steps: `kitmux skill add PATH`, move the original aside, then enable
the skill for its clients.

## Managed bridge

Upstreams may advertise capabilities beyond tools; only tools are bridged. Startup
is asynchronous with a 30-second budget, retries with backoff, and status reports
`starting` while an upstream initializes. A crashing upstream no longer causes a
relist loop. Sockets of exited bridges are pruned, messages are forwarded
byte-for-byte with 512 levels of nesting, upstreams receive EOF before termination,
in-place catalog edits are observed, and reconnect reports each failure reason.
Codex currently only logs `tools/list_changed`, so a running Codex session shows
managed tool changes after a restart.

## Upgrade and rollback

Install v0.6, restart coding clients so managed bridges load the new executable,
then run `kitmux sync --preview` and `kitmux sync --apply`. This applies native
changes that earlier conflicts may have blocked. No catalog migration is needed.

The ownership journal gains two optional keys, `subagent_agents` and `skill_rules`.
v0.5.0 can still read v0.6 catalogs and journals, but its next sync reapplies v0.5
behavior, including disabled MCP entries in unassigned clients. The skill store is
read-only; restore write permission (`chmod -R u+w`) before deleting it by hand.
Clients that an earlier `subagent import` made fully managed stay managed until
`kitmux restore --agent CLIENT` and re-adoption.
